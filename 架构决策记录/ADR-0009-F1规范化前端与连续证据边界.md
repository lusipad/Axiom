# ADR-0009：F1 规范化前端与连续证据边界

> 状态：Accepted  
> 日期：2026-08-11  
> 影响范围：FiveAxisTrajectoryPack M0～M2、Reference Solver、证据等级、Web UI

## 背景

Math F1 是第一个产生五轴数学正向结论的阶段。它必须同时避免两类失真：一是把厂商 G-code、机器轴角和任务刀轴混为同一语义；二是把有限采样、可选网格碰撞后端或可视化结果标为连续认证。

完整 RS274、CLDATA、STEP-NC、NURBS CAD 和一般网格布尔内核的组合范围远超首个可复现参考栈。F1 仍需要一个真实文本入口、连续位置/姿态对象、确定性对应关系以及有明确适用域的任务几何碰撞证据。

## 决策

1. M0 的权威输入是 `five-axis.normalized-program@1` JSON IR。首个文本前端定义为 `axiom-cl-subset@1`，只接受 `UNITS`、`FROM`、`GOTO`、`FEDRAT`、`DWELL`、`END` 的严格子集；它借鉴 CL 刀位/刀轴表示，但不声称完整 ISO 3592 或厂商方言兼容。
2. 首个 `FROM` 必须显式给出单位刀轴 IJK。后续省略 IJK 只能继承已显式建立的模态刀轴，并在规范化事件中记录来源；未知记录、非有限数、零刀轴、模态前置条件缺失和 `END` 后内容必须定位失败。
3. M1/M2 统一使用无量纲 `sigma ∈ [0,1]`。sampled Cartesian view 继续只是派生视图，不能作为连续真值或 `GeometryValid` 的唯一证据。
4. 首版位置内核复用 NumPy/SciPy 的解析/分段多项式与 B-spline 求值，姿态内核复用最短弧球面插值。Axiom 自己冻结定义域、对跖规则、容差、provenance、导数界和证书格式；第三方函数名不等同于领域证明。
5. `provenance-progress@1` 在进度 ID、版本和源段 lineage 一致时形成精确对应。`monotone-minimax@1` 必须输出规范结点、允许区间、目标上下界、并列规则、数值容差和求解器版本；只有有限离散近似时证据最高为 `Validated`。
6. 连续最大误差只有在解析结果或覆盖完整区间的保守上下界闭合时才能标为 `Exact` / `Certified`。有限采样和普通优化结果不得升级。
7. F1 的 Certified 碰撞适用域先限定为版本化解析刀具基本体、解析路径段和解析/AABB 工件、毛坯、夹具上下文；一般 mesh/CAD 后端只能作为能力可探测、固定版本的 `Validated` Adapter，缺后端时返回 `UnsupportedCapability`。
8. 将任务几何碰撞与 M3 配置空间碰撞能力拆开。F1 只允许 `GeometryValid` 和 `TaskGeometryCollisionFree`；禁止生成 `KinematicallyFeasible`、`ConfigurationCollisionFree`、`ModelCollisionFree`、`ContinuouslyFeasible`、`IntervalCertified` 以及设备安全/可执行声明。

## 被否决方案

- **先做完整 G-code 解释器**：会把控制器方言、机器轴语义和 F1 任务几何绑死，且不能改善连续证书。
- **用固定密度采样计算最大误差和碰撞**：演示简单，但会漏掉区间内部超差/碰撞，只能形成 `Validated` 诊断。
- **把 Trimesh/FCL 设为默认认证内核**：其碰撞后端是可选能力，版本和几何容差需要额外冻结，不能直接承担可移植证书。
- **在 F1 合并任务碰撞与机床配置碰撞**：M3 尚未产生轴配置路径，正向结论会越级。
- **用毫米与角度加权成一个误差**：量纲和权重没有普适语义，位置/姿态门槛必须分开。

## 后果

- F1 可以从真实、严格的文本输入进入 M0，同时让其他前端以后通过同一规范化 IR 接入。
- 解析 fixture 可以得到可复核的连续几何证据；一般曲线和网格能力会诚实保留 `Validated` / `Unsupported` 边界。
- Web UI 必须显示证据方法、对应策略、碰撞上下文和阶段边界，不能只显示一个“通过”徽标。
- 扩展完整 CLDATA、RS274、STEP-NC、NURBS CAD 或 mesh kernel 时，需要新增前端/后端能力与 fixture，不修改已冻结的 F1 结果语义。
