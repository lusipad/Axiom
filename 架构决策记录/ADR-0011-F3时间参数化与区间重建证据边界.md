# ADR-0011：F3 时间参数化与区间重建证据边界

> 状态：Accepted
> 日期：2026-08-11
> 修订：2026-08-12
> 影响范围：FiveAxisTrajectoryPack M3～M5、MotionConstraintProfile、Reference Solver、Web UI

## 背景

Math F2 冻结了配置路径 `q(sigma)`，但没有定义路径何时到达各个位置，也没有定义固定控制周期样本在相邻时刻之间代表什么。仅验证采样点会漏掉区间内部的速度、加速度、Jerk 或碰撞峰值；同一组 `q[k]` 在 ZOH、FOH、多项式与回看 M4 下也可能得到不同结论。

二阶固定路径时间参数化已有成熟的 reachable/controllable-set 方法；一般含 Jerk、分支、奇异性与几何自由度的联合全局最优问题仍不能作为首版已解决事实。F3 因而需要同时冻结“首个能严格证明的子集”和“超出子集时如何诚实失败”。

## 决策

1. F3 使用独立 `MotionConstraintProfile` 绑定 M3 MachineProfile 内容身份、逐轴速度/加速度/Jerk 上限、任务进给上限、边界状态、dwell 时长、结点策略、单位和 provenance。不得修改已发布的 `five-axis.machine-profile@1` 或从轴名、M2/F2 事件中猜测缺失动态语义。
2. M4 权威对象为版本化连续轨迹 Artifact。它必须绑定 M3 AxisPath 与 MotionConstraintProfile 的内容身份，显式记录每个移动/dwell 时间律区间、结点停启策略、连续 V/A/J 上界、验证方法、数值环境、误差账本与最优性状态。M4/M5 portable 内容身份继承 ADR-0010 的 8 位有效数字、signed-zero 哈希等价类和 raw gate 之后的 `1e-14` IK 残差证据 floor；连续约束、重建验证和 Claim 判定仍只使用原始 binary64 值。
3. 首个二阶已证最优子集限定为线性 `q(sigma)`、零端点速度、显式正速度/加速度界和无移动中间结点的 stop-to-stop block。它使用解析三角/梯形标量时间律，并由独立重放器复核边界状态和逐轴连续约束；只有该闭包可标记 `ProvenOptimal` 且 gap 为零。
4. 首个 Jerk 可行子集使用七次停到停 smoothstep：`s(tau)=35tau^4-84tau^5+70tau^6-20tau^7`。持续时间按逐轴约束和保守导数界确定；严格证书使用已冻结的代数上界与向外浮点舍入，多项式临界点/密网格只作为独立 `Validated` 交叉证据。该路径的最优性固定为 `FeasibleOnly`，不得升级为一般 Jerk 全局最优。
5. `dwell` 在 M4 中是 `sigma` 常量的显式时间区间。`mandatory-stop`、`branch-change`、`wrap`、`singularity-boundary` 与不具备三阶匹配证书的结点必须切成 stop/restart block；`collision-violation` 不能通过增加时间律变成正向数学 Claim。
6. M5 必须区分 `SampledTrajectory` 与 `DiscreteCommand`。固定周期方案使用 `[t_k,t_{k+1})` 区间，显式记录非整周期 remainder、终点样本和 final-hold；每个样本保留时间、周期索引、`sigma`、轴位置及可用导数、任务位姿、来源和精度。
7. 重建策略按版本化能力矩阵解释：
   - `reference-m4` 可在内容身份和采样/量化关系重验后继承 M4 连续证书；
   - `polynomial` 只对已冻结系数、阶次和解析导数覆盖的量生成区间证书；
   - `foh` 只覆盖位置、区间速度及明确支持的沿线查询，斜率跳变处不生成高阶连续正向结论；
   - 移动 `zoh` 不生成有限正速度/加速度/Jerk 上界，也不支持标准 `IntervalCertified` 正向 Claim。
8. F3 的标准正向 Claim 仅为 `ContinuouslyFeasible` 与 `IntervalCertified`。前者要求完整 M4 连续重验，若请求 Jerk 则每个移动开区间必须 C3 或由可验证停启边界隔开；后者要求绑定重建策略并覆盖 Case 请求的全部区间能力。
9. 误差账本按 quantity、unit、source、bound 和 method 分项保存。位置、姿态、时间、量化和浮点误差不得跨量纲直接求和；UI 也不得把它们压成无物理意义的单一“总误差”。
10. F3 仍是数学参考层。`ContinuouslyFeasible` 与 `IntervalCertified` 均不构成 `DeviceSafe`、`ProcessSafe`、控制器兼容或真实机床执行许可；R2 最终 Solver/SUT 集成阶段门仍属于 F4。

## 被否决方案

- **直接把 TOPP-RA 或 Ruckig 设为必选依赖和证书来源**：第三方求解结果不能替代 Axiom 的内容绑定与独立重验；Ruckig 的主问题还是状态到状态，而不是冻结 `q(sigma)` 后的时间参数化。
- **把七次 smoothstep 称为 Jerk 全局最优**：它提供可严格复算的可行轨迹，但不解决一般三阶固定路径最短时间问题。
- **只检查固定周期样本点**：会漏掉区间内部极值、跳变和重建策略差异。
- **把动态上限加入 F2 MachineProfile**：会静默改变已发布 schema 与内容身份，并混淆几何机器定义和本次运行约束。
- **把多量纲误差相加成总预算**：数值没有一致物理单位，也无法形成可移植比较。
- **让 ZOH/FOH 继承 M4 的全部 V/A/J Claim**：保持策略本身可能引入不连续，证据不能跨语义借用。

## 后果

- F3 可以先对窄但真实的 M3 子集发布可复算 M4/M5 正向 Claim，并为一般 TOPP/Jerk 算法保留版本化扩展面。
- 求解器和 verifier 必须分离；Runtime 不信任 Artifact 自报证书，而要重算内容身份、时间律、连续极值、结点策略、采样计划和重建能力。
- Web UI 必须同时呈现连续轨迹、采样命令和 reconstruction policy，并永久显示 `MATH ONLY / NOT DEVICE SAFE`。
- 以后若引入 TOPP-RA、Ruckig、区间算术库或厂商控制周期语义，应作为新的 Solver/Verifier/Policy 版本接入，不得改变本 ADR 已冻结结果。
