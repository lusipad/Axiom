# ADR-0012：v0.7 Windows 确定性发布基线

> 状态：Accepted
> 日期：2026-08-12
> 影响范围：CI、GitHub Release、F2/F3 fixture、RunBundle 数值环境、Web 构建产物

## 背景

F2/F3 portable Artifact 身份与指标结论在受测数值后端间保持一致，但精确 `RunBundle` 会封存原始请求、Artifact、provenance 与证据。Windows 本机和 GitHub runner 即使具有相同 Python、NumPy、SciPy、Pint、Pydantic、操作系统族和机器架构，也可能分别选择 SkylakeX 与 Haswell OpenBLAS core，导致不改变门槛结论的末位浮点差异进入 `requestHash`、`report.contentHash` 和最终 `bundleHash`。

v0.7 需要一个非空洞、可重放的发布门，同时本阶段不承担 Ubuntu/Linux 支持承诺。

## 决策

1. v0.7 唯一受支持的发布与阻断验收平台是 Windows AMD64 + CPython 3.12.10；Python 依赖由 `constraints/acceptance.txt` 冻结。
2. CI 与 Release 在进程启动前固定 `OPENBLAS_CORETYPE=Haswell`、`OPENBLAS_NUM_THREADS=1` 和 `OMP_NUM_THREADS=1`。F2/F3 的数值环境同时记录 system、machine、Python、NumPy、SciPy、Pint、Pydantic 及这三个执行策略字段。
3. 发布 fixture 必须在 `AXIOM_REQUIRE_ENVIRONMENT_BOUND_GOLDENS=1` 下唯一匹配环境记录，且 `bundleHashes` 必须覆盖全部场景；没有匹配记录、重复记录或覆盖不全都直接失败。
4. portable Artifact 内容身份继续使用既有数值等价类；精确 `RunBundle` 保留原始请求与 Artifact 差异，并只在完整环境匹配时冻结。不得把 portable 投影替代原始 Run 证据链。
5. CI 与 GitHub Release 均在 Windows job 内完成 Web 测试/构建、全量 Python 测试、wheel/sdist 构建和独立 wheel smoke。仓库文本与内置 Web 产物统一使用 LF，避免 Windows checkout 换行策略制造构建伪差异。
6. Ubuntu/Linux 暂不属于 v0.7 支持矩阵。以后扩展平台时必须新增环境金值、完整 CI 与发布 smoke，不得从 Windows 结果外推。

## 被否决方案

- **只把 GitHub runner 的新哈希抄入 manifest**：没有记录 core/thread 根因，runner 数值内核变化后会再次漂移。
- **把 request/artifact hash 改为 portable 投影**：会丢失精确 Run 对原始输入与证据的封存语义，混淆 portable Artifact 与 environment-bound Bundle。
- **缺少匹配金值时仅做两次同进程重放**：发布门会在最需要阻断时静默变成空断言。
- **把 Windows build 号加入数值环境**：build 号不是已观察到的数值差异来源，却会随 runner 镜像更新制造无意义失配。
- **继续用 Ubuntu 构建发布、只在 Windows 跑少量 fixture**：无法证明用户要求的 Windows-only 发布链本身可安装、可运行。

## 后果

- Windows CI、发布构建和环境绑定金值使用同一数值内核，精确 Bundle 可复算。
- portable Artifact 与精确 RunBundle 的职责保持分离；数学门槛仍使用 raw binary64，不因身份策略改变。
- Windows runner 的 Python/依赖/core/thread 任一变化都会在发布前显式失败并要求更新审计记录。
- v0.7 不对 Ubuntu/Linux 作兼容性或发布可用性声明；增加新平台属于后续显式扩展工作。
