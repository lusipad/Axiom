# ADR-0013：F4 使用进程内双实现验收与完整数学门禁

- 状态：Accepted
- 日期：2026-08-12
- 决策范围：R2 Math F4 Reference Solver/SUT 集成、M5 碰撞证书和 R2 退出门

## 背景

F0～F3 已冻结 M0～M5 的分层数学对象、几何/运动学/时间律和区间重建证据，但尚未形成可执行的 Reference Solver/SUT 配对验收。F4 还必须补齐按确切 `ReconstructionPolicy` 验证的 M5 配置碰撞，并把此前分散发布的标准数学 Claim 汇总为 R2 总门禁。

Core 的 `DomainRuntimeBinding` 只接收领域 request，不接收外层 `RunSpec.subjectId`。因此不能把外层 subject 当作 Reference/SUT 分派键，也不能假装现有通用 runtime 已经支持任意外部求解器执行。

## 决策

1. F4 首版只支持静态注册的进程内 Adapter，不动态加载用户模块，不执行任意文件或命令，不开放 RPC。
2. Reference 与 SUT 的 descriptor、subject、版本、role、invocation 和 receipt 都进入 F4 有类型 request，由 F4 evaluator 验证；外层 `RunSpec.subjectId` 只表示 F4 验收运行。
3. Reference 与 SUT 必须通过两条独立生成路径产生 M5 `DiscreteCommand`。仅重放既有 M5 的 subject 可用于 transport、完整性和篡改反例，但不能计入 F4 独立交叉验证。
4. 一次 Run 继续只有一个主 Artifact：被测 M5 `DiscreteCommand`。Reference M5、M0～M4、Profile、Policy、碰撞模型和 Adapter 收据作为有类型支持对象及内容身份进入 request/evidence，不创建 F4 mega-artifact。
5. M5 按时间区间和确切 reconstruction coefficients 重新验证配置碰撞。实现可复用 F2 的 polynomial extrema、AABB envelope 和 recursive refinement 数学原语，但 M5 使用独立的 `time interval` 结果/证书，禁止复用 F2 `ConfigurationCollisionEvaluation` 的 `sigma/segment/path claim` 协议。
6. `five-axis.domain-pack@5` 显式重算并重投影 R2 完整 7 条标准数学 Claim：`GeometryValid`、`TaskGeometryCollisionFree`、`KinematicallyFeasible`、`ConfigurationCollisionFree`、`ModelCollisionFree`、`ContinuouslyFeasible`、`IntervalCertified`。
7. `ModelCollisionFree` 只有在 M2 任务几何碰撞、M3 配置路径碰撞和 M5 reconstruction 区间碰撞三层均为正向且覆盖完整时成立。
8. 单次 F4 Run 负责配对结果；版本化 `F4StageAcceptanceReport` 聚合三类拓扑正例、Adapter 输入哈希失败、M5 区间内部碰撞和七个 gate 状态。F1～F3 的对应/重建策略、M2/M3 碰撞及可复现性契约继续由各阶段 fixture、manifest 和 Windows 全量发布测试守门；两部分共同构成 F4/R2 总门禁。
9. F4 的域内 cross-validation 不扩展 ordered-point 全局 comparison policy。
10. 当前实现、测试、打包和发布只以 Windows AMD64 + CPython 3.12.10 为阻断基线；Ubuntu/Linux 不在本阶段支持矩阵中。数学 schema 保持平台中立。

## 后果

- F4 可以在不向 Core 加入五轴分支的前提下验证两个执行身份、内容血缘和完整 Claim 面。
- 原始 Adapter 自报的成功、证书或 Claim 不能直接通过；evaluator 必须独立重算。
- 进程内 transport 无法直接运行外部厂商二进制。未来增加文件、子进程或 RPC 时必须建立新的 ADR，并保持 invocation/receipt、内容身份、失败和 provenance 等价。
- F4 通过仍只说明冻结数学模型内成立，不产生 `DeviceSafe`、`ProcessSafe`、控制器兼容或上机许可。

## 被拒方案

- 以外层 `RunSpec.subjectId` 选择 Reference/SUT：领域 runtime 看不到该字段，会造成不可验证的身份关联。
- 首版同时实现进程内、文件、子进程和 RPC：超出 F4 证明闭环所需范围，并引入不必要的执行与安全边界。
- 让重放型 SUT 充当独立交叉验证：只能证明传输和完整性，不能证明第二生成实现。
- 直接把 M3 碰撞证书继承到 M5：忽略 reconstruction interval 的真实行为。
- 让 F4 只发布下游 5 项简化 Claim：会丢失 `TaskGeometryCollisionFree` 与 `ConfigurationCollisionFree` 的标准审计面。
- 修改全局 ordered-point comparison：其兼容/距离语义不适用于五轴分层数学对象。
