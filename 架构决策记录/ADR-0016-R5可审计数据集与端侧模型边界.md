# ADR-0016：R5 采用可审计数据集快照与 Windows-only 端侧模型边界

- 状态：Accepted
- 日期：2026-08-12
- 决策范围：DatasetSnapshot、split/lineage/governance、R5-A 学习顺序、ModelBundle、typed API/UI、阶段双状态

## 背景

R4 已经把物理响应、标定、holdout 和现实验证边界拆开，但 R5 需要一个可训练、可审计、可回放的数据层。当前仓库仍以 Windows AMD64 + CPython 3.12.10 作为唯一阻断发布基线，而真实跨设备、跨工况的数据还没有进入稳定、可审计的 holdout 门。

如果把训练数据、治理、推理格式、在线学习和设备写回混到同一个实现里，就会发生三类问题：

1. 无法证明训练/验证/测试没有泄漏；
2. 无法证明目标运行面与训练实现独立；
3. 无法证明“模型能跑”不等于“设备能写”或“现实已闭合”。

第一轮可行性 spike 也已经证明，直接把所有轴一起做成通用学习头并不能先过门槛；R5 必须先以 X-only 残差头闭合合同片，再把真实泛化门单独保留。

## 决策

1. R5-A 只支持 Windows AMD64 + CPython 3.12.10。非 Windows 环境必须返回 `Skipped + UnsupportedRuntimePlatform`，不能产生正向学习声明。
2. `DatasetSnapshot` 是 R5 的主数据产品，且必须是不可变版本化对象。它要显式记录纳入规则、内容身份、谱系、split 清单、治理清单、已知覆盖空洞和授权边界。
3. `SplitManifest` 必须把连通身份组件分到 train/validation/test 中的唯一一个 split。连通组件至少包括 trajectory、task、device batch、source pair、采集会话、变换链和同一主体版本。split 时间只允许前进，训练只在 train 上 fit，validation 只用于校准，test 永远不参与训练或校准。
4. `DatasetGovernanceManifest` 是强制字段。缺少许可、用途、保留、脱敏或发布边界的快照必须拒绝。OpenLineage 和 MLCommons Croissant 可以作为交换词汇，但不是运行时依赖。
5. 学习顺序固定为 OOD 优先，其次 X-only 残差头。Y、Z、B、C 在没有新证据前保持 `NoValidatedImprovement` 或 `InsufficientExcitation`，不得伪造“全轴闭合”。
6. 第一版全轴方案未通过预声明的改善门，已被拒绝。当前冻结的 Windows 参考场景使用三个 F4 拓扑隔离 train / validation / test；X-only 残差头达到 50.43% in-domain RMSE 改善、83.33% 区间覆盖、100% OOD 探针检测，并保持约 `1.39e-17` 的训练/目标跨运行时差异。导出的权重固定为 15 位小数，以使 ModelBundle 身份不依赖 BLAS 内核选择。
7. 不确定性必须使用 group-disjoint validation 上的 split conformal 绝对残差半径。这个结论只在声明的 exchangeability 边界内有效；一旦跨设备、跨工况或时间漂移使 exchangeability 不能成立，就必须弃权或返回 `Inconclusive`。
8. `ModelBundle` 必须是 JSON 版可移植工件，冻结输入契约、预处理、权重、适用域、不确定性、OOD envelope、资源预算和训练/parity 回执哈希。
9. 训练实现与目标运行面必须分离。训练侧可以使用 NumPy，但目标侧必须是独立的纯 Python 解释器，直接消费 `ModelBundle`。ONNX 只作为后续 Adapter 候选，不作为首版锁定格式。
10. R5 的 API 与 UI 必须 typed，并通过 OpenAPI 发布显式 response model。UI 只能展示数据集谱系、split、覆盖空洞、残差、OOD、区间不确定性、bundle 预算和阶段状态，不得暴露写设备、在线学习或自动部署控件。
11. R5 维持双状态：`syntheticLearningContractStatus` 与 `realWorldGeneralizationStatus`。前者可以先闭合，后者必须保持 Open，直到跨设备、跨工况 holdout、冻结许可、校准、时间和坐标上下文都到位。
12. 在真实泛化门未闭合之前，R5-A 不得发布 `DeviceSafe`、`ProcessSafe`、`safe-to-run`、`reality validated` 或任何设备写回承诺。

## 后果

- 数据集、谱系和治理有了统一的审计边界，训练、验证、测试不再只是目录约定。
- 目标解释器可以在不引入训练栈的情况下复现推理，便于 Windows 发布和安装后 smoke。
- OOD 与区间不确定性被放在前面，R5 不会把“更像回归器”误当成“更可信的现实预测器”。
- ONNX 不再绑死首版格式，后续如果真的需要适配器，可以单独开新 ADR。
- R5-A 能闭合 synthetic contract slice，但不能替代 R7 的控制、权限和安全边界。

## 被拒方案

- **把原始样本随意拆分到 train/validation/test**：会把 trajectory、batch、task 或 source pair 的泄漏藏进结果里，审计无效。
- **把 train 和 calibration 混在一起 fit**：会污染 conformal 半径，破坏区间解释。
- **直接做全轴统一学习头**：第一轮 spike 已经证明它没先过改善门，不该继续伪装成主线。
- **把 ONNX 作为首版锁定格式**：会把端侧适配和合同片绑定过早，降低首版可审计性。
- **把目标解释器直接写成训练代码的同一份实现**：会让 parity 失去独立性。
- **把 learning 结果解释成设备安全或真实泛化闭合**：这会越过 R5 的边界，必须拒绝。
