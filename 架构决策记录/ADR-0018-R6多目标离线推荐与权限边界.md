# ADR-0018：R6 使用多目标离线 Recommendation，不把优化器接到设备写入

- 状态：Accepted
- 日期：2026-08-12

## 背景

R6 需要从用户目标反向寻找参数，但现有证据链仍是 synthetic SIL，R5 真实泛化门保持 Open，R7 的在线停止、权限和责任边界尚未实现。直接输出一个加权总分会混合秒、毫米和样本数；直接缩放已有 M4 又会让旧证书失真。

## 决策

首版使用固定两参数网格、完全枚举和确定性 Pareto。`feedOverride` 通过降额约束后重新规划；`samplePeriod` 只有在独立多采样率 holdout 覆盖后才进入搜索域。

搜索生成独立 `RecommendationSet`，公共 Domain runtime 对其确定性重放。Recommendation 与 AcceptanceRecord 分离，权限固定为 Offline，且设备写入和自动接受均为 false。R5 只注记 OOD 并阻断晋级，不承担物理目标。

## 后果

- 首版计算量可预测，两个独立实现可得到同一 Pareto 集和内容哈希。
- 不需要引入优化库或 surrogate 依赖。
- 候选可以解释“改善什么、牺牲什么”，但不能声称真实设备安全。
- 参数面扩大后可引入经过独立验证的 surrogate，但不得改变既有 Recommendation 身份和权限语义。

## 被拒方案

- 加权单分：量纲和偏好被隐藏，无法复现真实权衡。
- 直接缩放 M4 时间：破坏 F3 重新规划/验证语义。
- 用 R5 预测误差做首版目标：参数候选中大量 OOD，独立试验不足。
- 自动写入设备：R7 权限、停止和真实 holdout 尚未闭合。
