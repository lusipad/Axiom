# ADR-0020：R7-B 先冻结部署影子就绪性，不伪造厂商 Adapter

- 状态：Accepted
- 日期：2026-08-12

## 背景

R7-A 已闭合 Windows Synthetic Shadow 软件合同，但真实 deployment shadow 仍需要具体控制器、受控制器强制的最小权限、版本化厂商 Adapter、真实采集、时钟/信号映射和外部证据来源。当前尚未选择 Siemens、FANUC、HEIDENHAIN 或其他目标控制器，也没有可用于验收的设备、凭据和厂商运行环境。

在目标未选时实现一个声称支持真实设备的通用 Adapter，会把接口设想误写成已验证能力；直接把仓库 fixture 标为真实证据则会破坏 Axiom 的证据边界。

## 决策

新增 Windows-only `control.domain-pack@2`，一次 Run 的主 Artifact 为 `axiom.control.deployment-shadow-readiness@1`。R7-B 只评估部署影子的前置证据，权限上限仍为 `Shadow`，`deviceWriteAllowed=false`。

外部 `DeploymentShadowEvidenceSet` 必须分别携带：

- 版本化控制器 Profile；
- 由控制器执行点强制的 read/subscribe 权限证据，以及对参数写入、程序传输、cycle start、feed hold、reset、jog 和安全旁路的拒绝证明；
- 不可变 raw capture、Adapter Receipt、时钟/信号映射和外部 provenance；
- 交叉内容身份、连续序号、单调时间、采样/丢包和零写操作计数。

客户端不能只靠 JSON 自行把权限声明为可信。即使提交 `Verified`，在对应厂商 verifier、trust anchor 和目标控制器环境未接入前，vendor adapter 与 reality gate 仍保持 `Open`。仓库 `contract-fixture` 永远 `declaredReal=false`、`countsTowardReality=false`，只验证 schema、确定性和阻断路径。

## 后果

- 可以先稳定 Siemens OPC UA、FANUC FOCAS2、HEIDENHAIN OPC UA/DNC 等不同前端都必须满足的共同证据合同。
- 网页只提供证据导入与就绪性审查，不提供设备连接、参数写入或控制动作。
- 后续选定厂商后必须新增独立、版本化 Adapter 与厂商 verifier，并用控制器外部采集证据做 case-scoped 验收。
- R7-B 通过只表示合同片可用；真实 deployment shadow、Controlled Trial、Closed Loop、DeviceSafe、ProcessSafe 和标准符合性均未闭合。

## 被拒方案

- 同时实现三家厂商 Adapter：缺少设备和授权环境，无法验证真实协议行为，且扩大未验证攻击面。
- 先选一个“最常见”厂商：这会替用户做影响接口、许可和部署方式的产品决策。
- 允许上传 JSON 直接关闭现实门：内容自述不能替代控制器端权限、厂商 trust anchor 和外部采集证明。
- 复用 R7-A synthetic trace 作为真实 capture：合成状态机与真实控制器观测的证据来源不同。
- 在 Core 增加 `PhysicalModel` 或厂商权限枚举：现有 DomainPack、Profile、Adapter、Artifact 和 Evidence 足以表达，领域概念不应进入 Core。
