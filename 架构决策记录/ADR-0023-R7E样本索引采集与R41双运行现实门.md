# ADR-0023：R7-E 采用样本索引触发采集，R4.1 使用独立双运行现实门

- 状态：Accepted
- 日期：2026-08-13

## 背景

R7-D 已冻结 Beckhoff TwinCAT 3 Build 4026+ / TF6100 的厂商 Profile 与运行时验收，但普通 OPC UA publishing interval、DataChange 通知和主机时间戳不能证明每个 M5 指令样本都被观测。把异步通知直接按时间插值到 M5 会掩盖丢帧、重采样和控制器任务节拍差异，也会让后续物理模型在无法复现的对齐上拟合。

同时，单次真实 Shadow capture 既用于拟合模型又用于验证模型会形成数据泄漏。即使单次残差很低，也只能证明该运行的 replay，不能形成独立 holdout 的现实证据。

## 决策

新增 Windows-only `control.domain-pack@5` 与 `.NET` `beckhoff-shadow-capture`。控制器工程必须公开只读的 command content hash、`UInt32` sample index 和 X/Y/Z/B/C 轴位置。Adapter 只订阅 sample index；每次收到新索引后，以一次七节点 batch Read 读取 command hash、索引与五轴位置。验收固定要求：

- 从索引 0 开始，索引与 M5 `sampleIndex` 完全相等且连续；
- command content hash 与输入 M5 完全相等；
- 每个索引恰好形成一帧，不插值、不静默排序、不由 publishing interval 推导周期覆盖；
- source/server/host timestamp、quality、protocol sequence、读操作数与 transcript hash 全部留证；
- 生产路径的 Write 和 Method Call 计数必须为 0。

真实证据还必须绑定 `Bound` Vendor Profile、`vendor-runtime` R7-D 证据、控制器 Profile、经验证的只读 authority、数据所有者签署的 capture authorization 和精确 M5 内容身份。capture authorization 必须冻结带 UTC offset 的 `authorizedFrom` / `authorizedUntil`；receipt 的打开、关闭与 `capturedAt` 任一落在时间窗外均 fail closed。仓库 conformance 只产生 `contract-fixture`，不得计入 deployment Shadow 或 reality。

新增 `five-axis.domain-pack@7` 作为 R4.1 reality evaluator。它消费两个独立的 R7-E evidence pair：`calibration` 只用于拟合，`validation` 只用于 holdout。两者必须来自同一设备与 Case，但 pair、Shadow evidence、capture authorization 和采集时间窗必须不同。验证阶段不得重拟合；按 exact sample index 对齐，线性轴 `mm` 与旋转轴 `rad` 分组计算，并重验 command→model→observation 残差分解。

只有五轴均有足够激励、两次 R7-E deployment Shadow 均通过、独立性/同设备/采样周期/对齐/fit/分解全部通过时，`five-axis.physical-model-reality-validated-claim@2` 才能在 `single-device-case-scoped` 范围得到支持。该结论仍不等于 Controlled Trial、Closed Loop、DeviceSafe 或 ProcessSafe。

## 后果

- R7-E 能证明某一 M5 指令与一组真实只读轴样本的一一对应，不再把异步订阅频率冒充控制周期覆盖。
- R4.1 首次拥有可运行的真实双运行校准/holdout 合同，但仓库不内置任何伪造的真实正例；默认状态仍为 Open。
- 数据所有者授权成为现实证据身份的一部分；没有授权、复用同一 capture、contract fixture 或不同设备证据都会 fail closed。
- PhysicalModel schema 升级到 `five-axis.physical-model-definition@2`，显式绑定校准 command、Shadow evidence、控制器 Profile、Case ID、样本周期和 case-scoped applicability。
- 网页只导入并核验证据，显示 Shadow、calibration、holdout、reality 和安全状态，不连接 PLC、不写设备。

## 被拒方案

- 按 OPC UA publishing interval 直接采样五轴：通知聚合与抖动不能证明每个 M5 样本被覆盖。
- 用主机时间插值补齐缺失索引：会把不可观测区间伪装成完整证据。
- 对七个节点分别订阅并把最近值拼成一帧：无法证明同一索引下的一致读取语义。
- 用同一次 capture 拟合并验证：存在直接数据泄漏，不能形成 holdout Claim。
- 把两次不同文件名视为独立：必须同时比较内容身份、授权和采集时间窗。
- 从单设备单 Case 的低残差外推设备安全或跨工况可信度：现实拟合不授予执行权限，也不覆盖未建模因素。

### Questions for review

- 真实 TwinCAT 工程最终采用 PLC task 内递增 sample index，还是由 NC/PLC 映射到已有控制器 cycle counter，需要部署方在绑定 Profile 中冻结。
- 当前尚缺经数据所有者授权的两次真实采集，因此 deployment Shadow 与 reality gate 仍为 Open。

### Verification

- `.NET 8.0.424` 解决方案无警告构建与 localhost conformance 通过；5 个索引分别触发 5 次七节点 batch Read，生产路径 Write/Call 为 0，Python 可重验输出哈希。
- Python R7-E / R4.1 DomainPack、API、非 Windows Unsupported、证据泄漏、contract fixture 阻断和独立 holdout 数学路径测试通过。
- 网页在 1280、768、375 像素宽度完成视觉验收，根页面无横向溢出，且不出现设备控制入口。
- 未连接真实 TwinCAT/TF6100，没有真实采集授权与双运行数据，未测试 Controlled Trial、Closed Loop、设备停止、回滚或功能安全。
