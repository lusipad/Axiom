# ADR-0028：先交付 CNC 算法对比与回归工作流

- 状态：Proposed，随本 PR 审阅
- 日期：2026-09-05
- 范围：近期产品路线、外部算法结果接入、主工作台和数值上界修正

## 问题

v0.22 已具备大量数学、物理、学习和部署合同，但 F4 仍主要比较同一 M4 的两种内部采样实现，R6 搜索仍使用固定内置案例。真实算法版本的接入、不同时间律的比较和回归定位应成为近期交付中心。

Draft PR #21 对目标的收缩有价值，但先建设新内核、证书和证明对象，到第 11–13 周才接入第一个 SUT，仍推迟了用户价值验证。本决策调整实施顺序，不把该 Draft 的新理论或新内核视为本次代码依赖。编号 0027 为该 Draft 保留。

## 决定

1. 默认工作流为同一案例下的外部算法 A/B 轨迹比较。文件格式先行，接入 C++、C#、Lua 或其他生产端导出的结果；不添加任意进程执行器。
2. 在应用层增加一个小型比较入口，复用 Pydantic、Python、CLI、HTTP 和现有前端。不新增 DomainPack，也不先重写 Core。
3. 首版明确限制为采样 XYZ 命令。独立计算路径偏差、首尾、行程和离散 V/A/J；不使用内置 SUT 给自身作参考，不把不同合法时间律判为不一致。
4. 运动时间、几何偏差和可比较的实际计算耗时分开，不建立万能总分。存在取舍、缺失测量和超限时明确表达。
5. R5–R7 及其现场合同保留为参考/实验能力，近期不继续横向扩展。通过“参考与实验功能”访问，不自动初始化或阻塞新的主工作流。
6. 既有采样证书中的 power-sum 上界使用精确有理数复核并向外舍入，保留原先已足够保守的值。该修正只包围输入 binary64 系数对应多项式的 power-sum，不宣称其系数推导过程已获整体区间证明。

## 验收与后续

本次实现要能导入、比较、定位、下载和重放；要拒绝不同案例、单位、坐标系和时钟，以及缺失、重复和乱序样本。已知合成回归必须定位到具体样本。

生产有效性仍等待用户团队提供真实算法导出和刀路。下一里程碑是一次真实版本对比及独立重放，再按结果决定连续检查、Orion 或计量投入。离线回归可以单独交付，现实声明必须等待对应现实证据。

## 替代方案

- 直接把外部算法塞进现有 F4：会要求它消费已有 M4，并沿用采样实现等价性问题，无法覆盖真实规划版本差异。
- 先实现 Evidence Kernel v2：近期算法接入没有展示出必须重建内核的证据。
- 将采样差分标记为连续证书：无法推出控制器在采样间的实际行为，拒绝。
