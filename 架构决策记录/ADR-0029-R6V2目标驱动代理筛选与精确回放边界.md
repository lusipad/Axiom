# ADR-0029：R6 v2 使用目标驱动代理筛选，最终推荐只来自精确回放

- 状态：Accepted
- 日期：2026-08-13
- 决策范围：R5-C 到 R6 的消费边界、目标表达、搜索预算、精确验证、最优性声明和设备权限

## 背景

R6 v1 用六点完全枚举证明了反向推荐链可以闭合，R5-C 又提供了带空间 holdout、conformal 区间和域外弃权的双输出条件效应模型。下一步需要扩大参数搜索面，但不能让代理预测替代数学或物理模型，也不能把三个异质量纲目标混成难以解释的权重总分。

在冻结的 15×9 参数网格上直接取三目标代理 Pareto 前沿没有足够筛选力：大多数点互不支配，无法稳定压入 27 次精确验证预算。用户真正提出的通常也不是“给我整个前沿”，而是“在两个明确限制下，优先改善某一个结果”。

## 决策

1. 新增 `optimization.domain-pack@2`、`optimization.search-request@2` 和 `axiom.optimization.recommendation-set@2`；R6 v1 的对象、哈希、运行时与 API 保持不变。
2. 首个 R6 v2 搜索面固定为 `feedOverride=0.65..1.00`、步长 `0.025`，以及 `samplePeriod=0.04..0.08 s`、步长 `0.005 s`，合计 135 个候选。
3. 每个请求必须明确一个主目标，并为另外两个目标提供同量纲上限。主目标只允许周期、线性跟随误差或指令样本数；不支持权重、综合评分或缺失约束。
4. R5-C 对全部 135 点生成带区间的周期和线性误差预测；指令样本数由预测周期与采样周期确定。代理只能判定“可能可行”并排序，不能产生最终 Recommendation。
5. 排序采用主目标区间下界、主目标预测值、`feedOverride`、`samplePeriod` 的确定性顺序；连续目标在代理排序时冻结到微秒级，避免数值噪声改变同等候选次序。精确裁决仍保留完整数值精度。
6. 每次最多选择 27 个候选执行精确 F3/F4/R4 回放。最终可推荐候选必须同时通过七个数学 Gate、R4 适用性和用户的两个精确约束；代理“可能可行”永远不能覆盖精确失败。
7. 输出只声明 `best-observed-within-exact-validation-budget`。`globalOptimalityStatus` 固定为 `NotClaimed`；精确验证集内可以报告 Pareto 与主目标并列最优，但不得外推为全局最优。
8. R6 v2 继续固定 `permissionLevel=Offline`、`deviceWriteAllowed=false`、`automaticAcceptanceAllowed=false`、`realityValidationStatus=Open`。Recommendation 不构成 AcceptanceRecord、DeviceSafe、ProcessSafe、上机许可或设备写入授权。
9. Windows 是当前唯一支持平台。Python、HTTP 和公共 Run 必须重放同一搜索并验证完整内容身份；打包夹具冻结代理上下文、筛选回执、Recommendation 和最佳已观测候选身份。

## 后果

- 用户可以从“看整个 Pareto 前沿”进入“定义目标与两个边界”，同时仍能看到代理筛选、精确回放和拒绝原因。
- R5-C 成为有版本的搜索加速器，而不是新的真值层；数学与物理模型仍是最终裁决者。
- 135 个代理评估只消耗最多 27 次精确回放，搜索成本有明确上界。
- 当前结论只覆盖冻结网格、canonical 路径和 synthetic SIL 物理合同；真实设备泛化和自动闭环没有因此推进。

## 被拒方案

- **直接取代理三目标 Pareto 前 27 个点**：冻结网格上前沿过密，不能形成有效预算筛选。
- **把三个目标加权成总分**：隐藏秒、毫米和样本数的量纲与用户取舍。
- **把代理可行性直接作为 Recommendation**：会把估计升级为数学和物理结论。
- **宣称 135 点网格的全局最优**：只有最多 27 点经过精确回放，代理误差和网格外空间都未被排除。
- **原地修改 R6 v1**：会改变既有内容身份、API 和可复现语义；新能力必须使用 v2 合同。
- **把结果直接送入 R7 或设备**：现实 holdout、部署 shadow、受控试验与设备安全门仍未关闭。
