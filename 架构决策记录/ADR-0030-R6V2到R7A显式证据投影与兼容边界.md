# ADR-0030：R6 v2 通过显式证据投影进入 R7-A Shadow

- 状态：Accepted
- 日期：2026-08-13
- 决策范围：R6 v2 Recommendation 到 R7-A synthetic-shadow 的版本兼容、证据身份、候选入场和权限边界

## 背景

R6 v2 已能在 135 点参数面上用代理筛选候选，并对最多 27 点重新执行 F3/F4/R4 精确回放。既有 R7-A 只接受 `RecommendationSet@1`，运行器直接读取 v1 `candidates`；若把 v2 强转成 v1，会丢失 screening receipt、exact candidate、预算内最优性和代理不得裁决的边界。若复制一套新的 Shadow 状态机，又会造成权限、Stop、Rollback 和审计语义分叉。

## 决策

1. R7-A 保留 `control.domain-pack@1`、`axiom.control.runtime-audit@1`、`control-shadow-evaluator@1` 和现有状态机；主 Artifact 与六项 Claim 不变。
2. DomainPack 的只读 Recommendation context 显式声明同时支持 schema version 1 和 2。R7-A v1 的输入、输出、API 和计算语义保持不变；内容身份在冻结的开发/发布数值环境内分别保持不变。
3. R6 v2 进入 R7-A 时必须携带 `axiom.control.recommendation-evidence-projection@1`。该对象由 `axiom.adapter.r6v2-to-r7a-shadow@1` 确定性生成，绑定 Recommendation、SearchRequest、surrogate context、screening receipt、exact candidate 和 screening estimate 的内容身份。
4. Projection 记录 `ExactEligible/ExactIneligible`、`BestObserved/ParetoWithinValidated/ExactEligible/ExactIneligible`、预算内最优性和 `globalOptimalityStatus=NotClaimed`，但它不是 `AcceptanceRecord`，也不自动决定处置。
5. 任一通过精确数学/物理硬门和用户 exact constraints 的候选都可由独立 R7 处置进入 synthetic Shadow；默认场景选择 R6 v2 `bestObservedCandidateIds` 的第一项。非 best 的 exact-eligible 候选仍可被显式选择，避免把 Optimizer 的排序变成自动批准。
6. 缺 Projection、身份不一致、候选未进入 exact validation、精确硬门失败或 exact constraints 失败时必须 fail closed。代理的 `possiblyFeasible` 不得作为 Shadow 入场证据。
7. v2 AcceptanceRecord 的 `evidenceSnapshotHash` 指向 Projection，而 `recommendationSetContentHash` 继续指向原始 Recommendation；两者均保持不可变且 AcceptanceRecord 有独立内容身份。
8. 权限上限继续是 `Shadow`，所有设备 write/stop/ack/readback 均为 false。Deployment Shadow、Controlled Trial、Closed Loop、现实验证和标准符合性不因本投影升级。

## 后果

- R6 v2 的精确候选可以进入现有可复验 Shadow 状态机，而不伪装成 v1 或复制控制运行时。
- 公共 Run provenance 增加 Projection 内容身份；篡改 Recommendation、候选或 Projection 均会在发布 Claim 前失败。
- Controlled Runtime 网页默认展示 v2 接力，并保留 v1 切换；界面不增加设备连接或控制入口。
- R7-B–R7-E 仍是独立证据门，本决策不把 synthetic Shadow 自动串成真实 deployment Shadow。

## 被拒方案

- **把 RecommendationSet@2 降级为 v1**：会丢失代理筛选与精确裁决边界，并制造错误的 v1 内容身份。
- **新增第二套 R7-A DomainPack 和 RuntimeAudit**：状态机与安全边界没有变化，复制实现会产生不必要分叉。
- **只凭 surrogate screening 入场**：把估计升级为数学/物理事实，违反 R6 v2 的精确裁决合同。
- **只允许 best-observed 候选入场**：会让 Optimizer 排序替代独立 AcceptanceRecord 的处置责任。
- **直接接入 R7-B–R7-E 或设备**：当前仍缺具体部署证据、真实只读 capture、设备侧停止/回退和安全论证。
