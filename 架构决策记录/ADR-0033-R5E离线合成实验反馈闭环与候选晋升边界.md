# ADR-0033：R5-E 离线合成实验反馈闭环与候选晋升边界

- 状态：Accepted
- 日期：2026-08-13
- 决策范围：R5-D 实验计划、R4 synthetic SIL 标签采集、R5-C 数据/模型版本与后续重规划

## 背景

R5-D 已能从冻结的 R5-C/R6 v2 设计空间中规划下一批 synthetic SIL 参数点，但它刻意停在 `NotExecuted` 和 `NotPerformed`。如果将计划、仿真执行、标签获取、数据更新、候选模型训练与晋升隐式合并，将无法回答“谁批准了哪些实验”、“标签是哪个物理响应生成的”、“验证/测试是否被主动采样污染”以及“候选通过是否等于已晋升”。

当前仓库只有 Windows 本地的 canonical F3/F4/R4 synthetic SIL 求值链，没有经授权的真实设备试验、设备写入、模型注册表或自动回滚机制。因此本阶段只能闭合离线合成证据循环，不能借“闭环”之名扩大现实或设备权限。

## 决策

1. R5-E 是应用层的 Windows-only 离线编排：`R5-D plan → 显式批准 → exact F3/F4/R4 replay → 不可变 acquisition receipt → v2 Dataset/Split/Model candidate → 下一份 R5-D plan`。它不新增 DomainPack，不修改 Core。
2. 执行前必须由明确责任方批准完整五点批次。批准必须绑定计划内容哈希、proposal 全量且有序的实验 ID、责任方与 synthetic-only 确认；缺失、部分批准或错配均在首个物理回放前 fail closed。
3. 每个 proposal 必须重放既有 canonical F3/F4/R4 求值链，通过全部数学/碰撞硬门后才生成周期 `s` 和线性跟随误差 `mm` 标签。采集回执按顺序绑定 proposal、M4、M5、`PhysicalResponseTrace`、数值环境和标签身份，不连接或写入设备。
4. R5-C v1 的 25 点 Dataset、15/5/5 Split、ModelBundle 及内容身份保持不变。R5-E 发布独立 v2 对象：数据集按原顺序保留前 25 点，再按 proposal 顺序追加 5 点；split 为 20/5/5，新数据只追加到 train，原 validation/test 成员、顺序和职责完全冻结。
5. 候选模型必须重新训练、重算 conformal 半径和 parity，并在原 validation/test 上与基线逐指标比较。Campaign 执行成功、candidate gate 通过与模型晋升是三个独立状态；首版固定 `modelPromotionStatus=NotPerformed`。
6. 冻结 fixture 上的 holdout 指标改善只记录为可复算观测，`generalImprovementGuarantee=NotClaimed`。G-optimal leverage 优化设计空白，不保证预测精度、现实收益或安全性一定改善。
7. 获得五个新标签后，下一次 R5-D 只用 20 个 train 点构造信息矩阵，从 135 点中排除全部 30 个已观测点，在 105 点中产生新计划。新计划仍是 `NotExecuted`，不递归触发第二批实验。
8. 全链固定 `permissionLevel=Offline`、`automaticExecutionAllowed=false`、`deviceWriteAllowed=false`、`realWorldGeneralizationStatus=Open`。该结果不生成 `DeviceSafe`、`ProcessSafe`、真实设备许可或现实泛化声明。

## 后果

- 系统首次形成了可追溯的 synthetic `plan → approve → acquire → train → replan` 证据链，但人工责任点和模型晋升点仍清晰可见。
- 旧 v1 重放和内容金值不受影响；v2 对象通过 parent/acquisition 内容身份表达来源。
- 固定 validation/test 避免了将主动采样点回流到验收集造成的乐观偏差。
- 后续如需真实设备实验、持久模型注册、人工晋升或回滚，必须新增独立权限、治理和验收合同，不能复用 synthetic 批准绕过。

## 被拒方案

- **直接改写 R5-C v1 Dataset/Split/ModelBundle**：会破坏已发布的内容身份和确定性重放。
- **规划完成后自动执行、递归重规划**：没有显式责任点，且会把一个有限批准扩张成无界授权。
- **重新随机切分 30 点数据**：会污染原 holdout，使基线/候选指标不可比。
- **candidate gate 通过后自动替换生产模型**：当前没有模型注册、审批、部署和回滚合同，且 synthetic holdout 不支持现实晋升。
- **把单个 fixture 的 RMSE 改善声明为一般收益**：试验设计准则不保证任意数据生成过程下的模型精度改善。
- **为闭环另建 Core 对象或 DomainPack**：当前只是已有 typed 应用对象的有序编排，新增公共语义会扩大复杂度而不增加证明力。
