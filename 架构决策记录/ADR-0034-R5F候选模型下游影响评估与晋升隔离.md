# ADR-0034：R5-F 候选模型下游影响评估与晋升隔离

- 状态：Accepted
- 日期：2026-08-13
- 决策范围：R5-E 候选模型、R6 v2 surrogate context、下游决策影响证据与模型晋升边界

## 背景

R5-E 已能生成通过原 holdout 非回归门的 v2 候选模型，但 holdout 指标改善并不能回答候选作为 R6 v2 筛选器时是否会改变有限精确预算内的最终决策。若直接把候选替换为默认模型，会同时改变既有 `search-request@2` 语义、已冻结内容身份和生产选择状态，也会把“可评估”误写成“已晋升”。

当前仓库只有 Windows synthetic SIL、固定 135 点设计空间和每场景 27 次 exact F3/F4/R4 回放预算，没有模型注册表、审批部署、回滚、真实跨设备 holdout 或设备写入通道。因此本阶段只能形成候选下游影响证据，不能完成模型晋升。

## 决策

1. R5-F 是 Windows-only 应用层评估，不新增 DomainPack，不修改 Core，也不替换默认 R6 v2 模型。
2. 既有 `optimization.search-request@2`、`axiom.optimization.recommendation-set@2`、R5-C v1 context 和双环境金值保持不变。R5-E v2 候选使用独立 `optimization.search-request@3` 与 `axiom.optimization.recommendation-set@3`，避免扩大旧对象含义。
3. 候选 context 必须逐项绑定并重验 candidate ModelBundle、TrainingReceipt、ParityReceipt、Dataset、SplitManifest、CandidateAssessment 与 source CampaignReport 的内容身份。评估前必须重放 R5-E 报告，不能接受客户端自报的 RecommendationSet。
4. 评估固定覆盖 R6 v2 的周期、线性误差和指令数三个意图。基线与候选必须使用同一 15×9 网格、同一约束、同一确定性排序规则和同一 27 次精确预算。
5. surrogate 只允许改变候选筛选与顺序。进入预算的点继续逐一执行 F3/F4/R4；七个数学/碰撞门、R4 适用性和精确约束不得被代理结果覆盖。
6. 逐场景报告必须保存筛选集合重合/差异、精确集合、预算内最佳目标、退化状态和共享精确点上的预测误差差值。预测误差差值只用于诊断，不替代精确目标门。
7. 只有三个场景都保持 135/27 合同，且候选没有丢失基线预算内同等或更优的精确主目标时，`impactGateStatus` 才可为 `Passed`。该状态只描述冻结 synthetic SIL 决策场景，不声明一般收益、现实泛化或全局最优。
8. 报告永久固定 `candidateUseStatus=EvaluatedOnly`、`modelPromotionStatus=NotPerformed`、`permissionLevel=Offline`、`automaticModelPromotionAllowed=false`、`deviceWriteAllowed=false` 与 `realWorldGeneralizationStatus=Open`。UI 只提供影响评估，不提供采用或晋升按钮。

## 后果

- 候选训练验收和下游决策影响成为两个可独立失败、可审计的门。
- 旧 R6 v2 合同、重放和内容金值不受影响；候选消费路径具备独立版本和完整谱系。
- 影响报告可以说明筛选顺序变化是否影响预算内精确结论，但不能授权默认替换、部署或设备动作。
- 后续模型晋升必须另行设计注册、责任批准、版本切换、回滚、真实 holdout 和运行监控合同。

## 被拒方案

- **直接让 `search-request@2` 接受 v2 候选**：会扩大已冻结对象语义并破坏旧内容身份的可解释性。
- **候选 gate 通过后自动成为 R6 默认模型**：缺少独立下游影响、注册、批准和回滚证据。
- **用代理预测误差直接裁决 Recommendation**：会绕过 exact F3/F4/R4 与数学硬门。
- **扩大精确预算以消除候选退化**：比较条件不再一致，会掩盖筛选器对固定资源决策的真实影响。
- **把三个物理量合成总分**：破坏秒、毫米和样本数的量纲与用户显式约束。
