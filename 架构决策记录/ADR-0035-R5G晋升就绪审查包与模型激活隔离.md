# ADR-0035：R5-G 晋升就绪审查包与模型激活隔离

- 状态：Accepted
- 日期：2026-08-13
- 决策范围：R5-E/R5-F 证据移交、候选模型独立审查、模型注册与激活边界

## 背景

R5-E 已产生通过候选门的 v2 模型，R5-F 也已在冻结的三个 R6 v2 场景中证明候选未损害有限预算内的精确主目标。然而“证据足以提交独立审查”仍不等于“模型已经获批晋升”。当前仓库没有模型注册表、授权审批主体、默认版本指针、激活读回、可执行回滚或运行时监控，也没有可关闭现实门的独立真实 holdout。

如果直接增加“采用候选”动作，会把 synthetic 证据完整性误写成治理决定，并跳过注册、激活、回滚和监控等独立门禁。因此需要先建立一个只读、内容寻址且可复核的晋升就绪审查包。

## 决策

1. R5-G 是 Windows-only 应用层证据编排，不新增 DomainPack，不修改 Core，不持久化模型，也不改变默认模型。
2. `ModelPromotionReadinessDossier` 必须引用完整 R5-F 报告，并在生成时重放 R5-E 与 R5-F。来源 Campaign、影响报告、重放报告、基线模型、候选模型和候选 context 的内容身份必须一致。
3. `ReadyForIndependentReview` 只表示五项证据完整性检查通过：R5-E candidate gate、R5-F impact gate、R5-F 确定性重放、唯一候选谱系和旧基线回滚绑定。它不是 PromotionDecision，也不是人工批准状态。
4. 请求中的 `preparedBy` 和三项确认只证明审查准备者已看见 reality Open、尚未建立设备安全性和禁止自动部署的边界；不得解释为有权限的模型批准人。
5. 审查包必须把真实 holdout、独立人工决定、模型注册表、激活与默认切换、回滚执行和运行时监控六项门禁逐项保持为 `Open`。
6. 结果永久固定 `reviewDecisionStatus=AwaitingIndependentHumanDecision`、`candidateUseStatus=EvaluatedOnly`、`modelPromotionStatus=NotPerformed`、`defaultModelChanged=false`、`modelRegistryWritePerformed=false`、`activationPerformed=false`、`automaticDeploymentAllowed=false`、`deviceWriteAllowed=false` 和 `realWorldGeneralizationStatus=Open`。
7. UI 只允许生成和查看审查包，不提供采用、注册、激活、设为默认、部署或设备写入动作。
8. HTTP intake 必须按冻结的 `optimization.r6v2.feed-and-sampling@1` schema 把 JavaScript 丢失小数词法的 `feedOverride` / `samplePeriod` 整数恢复为浮点坐标后再验哈希；不得因此修改全局哈希算法或既有 R6/R5 金值。

## 后果

- 候选证据可以作为单一、可重放、可移交的审查材料，而不会改变任何运行状态。
- 基线回滚身份在晋升之前显式冻结，但当前阶段不声称回滚已经可执行。
- 后续真正的模型晋升必须另行引入可验证的授权主体、PromotionDecision、注册表写入、激活读回、回滚执行、真实 holdout 和运行监控合同。
- 任一来源身份、派生状态、平台或确认不满足时必须 fail closed；不得用 synthetic fixture 关闭现实门。

## 被拒方案

- **R5-F 通过后直接切换默认模型**：缺少独立治理决定、注册、激活读回和回滚证据。
- **把 R5-E 的批次批准复用为模型晋升批准**：批准对象和责任范围不同，会扩大既有证据含义。
- **先实现内存中的模型注册表**：无法提供持久性、权限、激活读回或崩溃恢复，只会制造伪完成状态。
- **把准备者确认命名为人工批准**：会混淆“看见风险边界”和“承担晋升决策责任”。
- **用 synthetic 影响门代替真实 holdout**：不能证明跨设备、跨工况现实泛化。
